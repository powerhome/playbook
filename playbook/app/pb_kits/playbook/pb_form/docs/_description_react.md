Build React forms by pairing Playbook form kits with [react-hook-form](https://react-hook-form.com/).

Use `Controller` for every kit in these examples. A few kits are plain DOM elements and would technically work with `register`, but `Controller` keeps the bindings consistent and covers the ones that aren't:

- **Plain inputs** (Text Input, Textarea, Checkbox, Date Picker, Time Picker, Phone Number Input): `onChange` fires a DOM event, so `field.onChange(event.target.value)` (or `event.target.checked` for Checkbox) works. `Controller` is used anyway so validation and default-value patterns read the same way across all kits.
- **Controlled widgets and kits whose `onChange` sends a value instead of an event** (Typeahead, Star Rating, Multi Level Select): `onChange` fires with the selected value (an object or array for Typeahead and Multi Level Select; a number for Star Rating). Bind through `Controller` and pass the emitted value straight to `field.onChange`.
- **`Select`** forwards a ref to the underlying `<select>` and its `onChange` forwards a `ChangeEvent`, so `register("field")` would work for value binding. The examples still use `Controller` for consistency, plus `blankSelection` so an empty default renders a real option.
- **`Dropdown`** does **not** forward a ref to a native element — its `forwardRef` exposes an imperative handle with `clearSelected` only, no `.focus()`. That means `register("dropdownField")` breaks any focus-management pattern that calls `.focus()` on the registered ref (most commonly react-hook-form's `setFocus` on validation error). Always bind Dropdown through `Controller`, and translate its emitted option node (`{ target: { name, value } }`, where `value` is a single option or an array for `multiSelect`) into form state via `field.onChange(event.target.value)`.
